Руководство по подключению плагина WebChat

Это руководство поможет установить и настроить WebChat Channel Plugin в OpenClaw Gateway для подключения браузерного чата.

Предварительные условия
У вас уже должны быть готовы адрес Chat Server, appId и secret.
Текущий сервер: определяется…

1. Установка плагина

Выполните на машине с OpenClaw Gateway:

openclaw plugins install openclaw-webchat-plugin

2. Настройка openclaw.json

Отредактируйте конфигурационный файл OpenClaw Gateway ~/.openclaw/openclaw.json: добавьте в раздел channels конфигурацию WebChat.

Пример для одного агента (без bindings, используется маршрут по умолчанию):

{
  "channels": {
    "openclaw-webchat": {
      "enabled": true,
      "serverUrl": "wss://your-domain.com/plugin",
      "accounts": {
        "my-webchat": {
          "appId": "wch_a1b2c3d4e5f60708",
          "secret": "***"
        }
      }
    }
  }
}

3. Описание параметров

ПараметрОписание
serverUrlАдрес Plugin WebSocket Chat Server, обычно заканчивается на /plugin.
appIdИдентификатор данного WebChat App.
secretСекретный ключ для подключения данного WebChat App. Должен храниться только на стороне Gateway.
bindingsПри нескольких агентах связывают WebChat account с конкретным агентом. Для одного агента можно опустить.

4. Перезапуск Gateway

openclaw gateway restart

5. Проверка

Посмотрите статус канала:

openclaw channels list

Убедитесь, что openclaw-webchat установлен, настроен и включён.

Или используйте режим probe для подробного статуса:

openclaw channels status --probe

Пример корректного вывода:

WebChat dev-main: enabled, configured, running, dm:open, allow:*
WebChat dev-2nd: enabled, configured, running, dm:open, allow:*

Ключевые статусы: enabled (включено), configured (настроено), running (работает). Если все три присутствуют, всё в порядке.

6. Настройка нескольких агентов (необязательно)

Если один Gateway должен обслуживать несколько WebChat App, можно настроить несколько account и привязать их к разным агентам через bindings.

{
  "channels": {
    "openclaw-webchat": {
      "enabled": true,
      "serverUrl": "wss://your-domain.com/plugin",
      "accounts": {
        "dev-webchat": {
          "appId": "wch_dev0000000000000",
          "secret": "***"
        },
        "ops-webchat": {
          "appId": "wch_ops0000000000000",
          "secret": "***"
        }
      }
    }
  },
  "bindings": [
    {
      "agentId": "dev-agent",
      "match": {
        "channel": "openclaw-webchat",
        "accountId": "dev-webchat"
      }
    },
    {
      "agentId": "ops-agent",
      "match": {
        "channel": "openclaw-webchat",
        "accountId": "ops-webchat"
      }
    }
  ]
}

7. Частые проблемы

Как посмотреть статус канала

openclaw channels status --probe

Пример корректного вывода:

WebChat dev-main: enabled, configured, running, dm:open, allow:*
WebChat dev-2nd: enabled, configured, running, dm:open, allow:*

enabled (включено), configured (настроено), running (работает). Все три статуса должны быть на месте.

not configured

Обычно означает, что в openclaw.json отсутствует конфигурация openclaw-webchat.

  • channels.openclaw-webchat.enabled установлено в true
  • В accounts присутствует нужный account
  • В сценарии с несколькими агентами проверьте, что bindings[].match.accountId совпадает с именем в accounts

invalid_app

Обычно означает, что appId не существует или указан неверно.

  • appId скопирован полностью
  • Текущий appId принадлежит используемому Chat Server
  • serverUrl указывает на правильный Chat Server

invalid_secret

Обычно означает, что secret не соответствует appId или указан неверно.

  • secret скопирован полностью
  • secret принадлежит текущему appId
  • После изменения конфигурации выполнена команда openclaw gateway restart
